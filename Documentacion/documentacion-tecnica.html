Infraestructura

Arquitectura del sistema

toVeriAI sigue una arquitectura de tres capas desacopladas: frontend SPA, API REST y capa de datos. La IA se integra como servicios cloud externos (rotación round-robin entre 5 proveedores — ver AiOrchestrator) con fallback opcional a modelo local (Ollama/VeriAI) cuando ai.local.habilitado=true.

Análisis

POST/api/analizarJWT opcional
Analiza un artículo y devuelve score IMI con 7 dimensiones.

Body: 
{ "contenido": "texto o URL", "tipoEntrada": "TEXTO | URL",
  "forzar": false, "idioma": "es" }
Límites: Anónimo 1 texto/día · USER 6 textos + 3 URL/día (+1 de cada por bonus de racha, ver Racha, votos y fuentes seguidas) · PREMIUM/Admin ilimitado
Caché / dedupe "¿ya lo hemos analizado?": Actualizado en modo URL ya no se compara solo por URL+<24h: se calcula el hash del HTML recién scrapeado y se compara contra contenidoHash de la última solicitud para esa misma URL. Si coincide, se devuelve el resultado guardado sin llamar a la IA; si el medio editó el artículo (hash distinto), se reanaliza y la respuesta incluye contenidoActualizado: true junto con el score y la fecha del análisis anterior. En TEXTO/IMAGEN el hash se calcula sobre el texto tras normalizar espacios. El cupo diario del usuario solo se descuenta si hubo llamada real a la IA — antes se descontaba también en cache-hit.
GET/api/url-meta?url={url}
Extrae metadata de una URL: título, autor, fecha, nombre del medio.
GET/api/url-texto?url={url}
Extrae el texto completo de una URL usando JSoup.
GET/api/url-transparencia?url={url}
Extrae las páginas Sobre nosotros/Legal/Contacto del dominio (usadas para las dimensiones TRANSPARENCIA_MEDIO y AUTORIA en modo URL). Endpoint de solo lectura, reusado por el script de comparación de proveedores test-multi-api.py.
POST/api/imagen/titulo
Modo IMAGEN, paso 1/2: sube una imagen (multipart/form-data, campo imagen, máx. 5MB, PNG/JPEG) y Groq Vision identifica/genera un título editable por el usuario antes de analizar.
POST/api/analizar/imagenJWT opcional
Modo IMAGEN, paso 2/2: con el título confirmado, Groq Vision extrae el texto completo anclado a ese título y lo reintroduce en el pipeline de TEXTO (7 dimensiones). En background, si ai.local.habilitado=true, Ollama Vision (qwen2.5vl:7b) lee la misma imagen para comparar la fidelidad de extracción frente a Groq Vision.

Body: imagen (file), tituloNoticia, idioma
Límites: 3/día para USER (cuota propia), ilimitado PREMIUM/ADMIN, anónimos comparten el cupo global de 1/día con TEXTO.

Frontend · Nuevo

Exportación: tarjeta, sello e informe PDF

En AnalisisPage.jsx, el botón "Exportar" abre un menú desplegable con las opciones Tarjeta, Sello (solo si tipoEntrada === 'URL') e Informe PDF (solo esPremium) — cada una con acción de Compartir (Web Share API) o Descargar directa.

Tarjeta y sello IMI — captura a PNG

Componentes ShareCard y ShareSeal (src/components/share/): render de la tarjeta/sello IMI en un nodo oculto que se captura con la librería html-to-image (nueva dependencia frontend).

Gotcha resuelto: el nodo a capturar se ocultaba originalmente desplazándolo fuera de pantalla con left: -10000px, lo que producía capturas en blanco (el navegador no renderiza layout fiable fuera del viewport para algunas rutas de captura). Fix: ocultar con overflow: hidden sobre un contenedor de tamaño 0 en vez de desplazar el nodo lejos. Patrón a reutilizar si se exporta algo más a PNG en el futuro.

Sistema de puntuación

Sistema IMI

El Índice de Métricas Interpretativas (IMI) evalúa la credibilidad de un artículo en 7 dimensiones periodísticas independientes. Cada dimensión produce un score de alertas (0-5) y un análisis cualitativo.

Escala global

0 – 49 · Credibilidad baja
50 – 74 · Moderada
75 – 100 · Alta

7 dimensiones de contenido (TEXTO y URL)

1
Semántica
Coherencia y claridad del lenguaje del autor. Solo evalúa la voz propia del periodista — nunca las citas de fuentes. Peso: 6%
2
Verificación Factual
Contraste de hechos. Métrica principal: determina techo máximo en el score (alertas 3→máx 65, 4→máx 50, 5→máx 30). Peso: 26%
3
Sesgo
Sesgo editorial del periodista en su propia redacción. Las declaraciones de fuentes bien atribuidas no aumentan el sesgo. Peso: 12%
4
Fuentes
Calidad y atribución de fuentes. Nombre + cargo institucional = alertas 1. Fuentes vagas = alertas 2-3. Sin fuente = 2-3. Peso: 15%
5
Consistencia
Coherencia interna del texto. Solo con contradicción concita ≥1. Si el texto es coherente, alertas=0. Peso: 24%
6
Tono
Test de propósito: INFORMAR (0-2) vs PERSUADIR/ALARMAR (3-4). Titular sensacionalista + cuerpo neutral = alertas 3 igualmente. Peso: 12%
7
Cifras
Estadísticas y datos medibles sin fuente. Números coloquiales no computan. Peso: 5%

2 dimensiones de transparencia (solo modo URL)

Requieren scraping de las páginas del medio (Sobre nosotros, Aviso legal, Contacto) que se realiza en el momento del análisis URL.

8
Transparencia del Medio
Evalúa si el medio identifica quién lo posee (página "Sobre nosotros") y cómo se financia (página "Aviso legal"). NewsGuard criterios 7+8. Peso URL: 10%
9
Autoría
Identificación del autor del artículo: 0=nombre+cargo, 1=nombre sin cargo, 2=seudónimo, 3=Redacción, 4=sin autor, 5=autor falso. NewsGuard criterio 9. Peso URL: 5%

Fórmula de cálculo

Modo TEXTO (7 dims): score = round(100 − Σ(min(alertas_i/5, 1) × peso_i) × 100, 1 decimal)

Modo URL (9 dims): Pesos alineados con metodología NewsGuard (÷92.5 pts cubiertos): contenido = 81.08%, TRANSPARENCIA_MEDIO = 13.51%, AUTORIA = 5.41%. Misma fórmula.

Techo duro: Si verificacion_factual = 3 → score ≤ 65. Si = 4 → score ≤ 50. Si = 5 → score ≤ 30.

Racha de verificación

Lógica de caché / dedupe "¿ya lo hemos analizado?" Actualizado

Antes de llamar a la rotación cloud, el servicio compara el contenidoHash (SHA-256) del contenido recién obtenido contra el guardado la última vez para ese mismo contenido/URL, en vez de basarse solo en una ventana de 24h:

// Modo URL: se compara el hash del HTML recién scrapeado contra el de la última
// solicitud para esa misma URL — si el medio editó el artículo, el hash cambia
String hashActual = DigestUtils.sha256Hex(contenidoScrapeado);
Optional<SolicitudAnalisis> anterior = solicitudRepo.findTopByFuenteOrderByFechaCreacionDesc(url);

if (anterior.isPresent() && hashActual.equals(anterior.get().getContenidoHash()) && !forzar) {
    return mapearResultado(anterior.get()); // sin llamar a la IA, sin descontar cupo
}
if (anterior.isPresent()) {
    contenidoActualizado = true; // se adjunta scoreAnterior + fechaAnalisisAnterior en la respuesta
}

En modo TEXTO/IMAGEN el hash se calcula sobre el texto tras normalizar espacios (colapsar espacios repetidos/saltos de línea), para que variaciones triviales de formato no disparen un reanálisis innecesario. El parámetro forzar: true en el request omite el check en ambos casos. El cupo diario del usuario solo se descuenta cuando hubo llamada real a la IA — antes se descontaba también en cache-hit.

Parseo del JSON de respuesta

La IA devuelve un JSON con una clave por dimensión. Para cada una se crea una entidad Metrica:

private List<Metrica> parsearMetricas(String json, ResultadoAnalisis resultado) {
    JsonNode root = mapper.readTree(json);
    for (TipoMetrica tipo : TipoMetrica.values()) {
        JsonNode nodo = root.path(tipo.getClave());  // "semantica", "fuentes"…
        Metrica m = new Metrica();
        m.setTipo(tipo);
        m.setAlertas(nodo.path("alertas").asInt());
        m.setObservaciones(nodo.path("observaciones").asText());
        m.setFragmentosDetectados(arrayComoJson(nodo, "fragmentos_detectados"));
        m.setConceptosDetectados(arrayComoJson(nodo, "conceptos_detectados")); // Nuevo — helper genérico
        m.setResultado(resultado);
        metricas.add(m);
    }
    return metricas;
}

ImiCalculator

Componente Spring (@Component) que calcula el IMI. Expone tres métodos: calcular() para 7 dims, calcularUrl() para 9 dims, y calcularContenido() para extraer el score de contenido de un análisis URL.

Pesos — Modo TEXTO (7 dims, total = 100%)

Algoritmo de cálculo

private static final double[] PESOS = {0.06, 0.26, 0.12, 0.15, 0.24, 0.12, 0.05};

private double calcular(int[] alertas) {
    double penalizacion = 0.0;
    for (int i = 0; i < 7; i++) {
        // Normalizar alertas a [0,1] y ponderar
        penalizacion += Math.min(alertas[i] / 5.0, 1.0) * PESOS[i];
    }
    double score = Math.round((100.0 - penalizacion * 100.0) * 10.0) / 10.0;

    // Techo duro: verificacion_factual grave bloquea el score máximo
    if      (alertas[1] == 5) score = Math.min(score, 30.0);
    else if (alertas[1] == 4) score = Math.min(score, 50.0);
    else if (alertas[1] == 3) score = Math.min(score, 65.0);
    return score;
}

El techo duro garantiza que ningún artículo con 5 alertas en verificación factual pueda superar 30 puntos, independientemente de las otras dimensiones.

AiOrchestrator

Servicio Spring que abstrae qué modelo IA responde a cada análisis. Desde el 2026-07-10, la llamada de puntuación (TEXTO/URL, y el paso final de IMAGEN) ya no depende de un único proveedor: rota en round-robin entre 5 APIs cloud, con failover automático si una falla.

Rotación cloud: Cerebras → Gemini → Mistral → SambaNova → Cloudflare

Groq quedó fuera de esta rotación (2026-07): en pruebas con noticias falsas daba sistemáticamente notas IMI más altas (peor detección) que Cerebras/Gemini. GroqAiClient se mantiene, pero solo para Groq Vision (extracción de título/texto en modo IMAGEN) — eso no cambió.

// AiOrchestrator.java — orden de preferencia, se salta el que no tenga API key
this.rotacionCloud = List.of(cerebras, gemini, mistral, sambanova, cloudflare);

private RespuestaCloud completarConRotacion(String prompt, String contenido, int maxTokens) {
    List<AiClient> disponibles = rotacionCloud.stream().filter(AiClient::disponible).toList();
    int inicio = rotationIndex.getAndIncrement() % disponibles.size();
    // Prueba cada proveedor empezando por "inicio"; si uno falla (rate limit,
    // 5xx, excepción de red) reintenta automáticamente con el siguiente
    for (int i = 0; i < disponibles.size(); i++) {
        AiClient candidato = disponibles.get((inicio + i) % disponibles.size());
        try {
            return new RespuestaCloud(candidato.completar(prompt, contenido, maxTokens), candidato.getModeloId());
        } catch (Exception e) { /* probar el siguiente */ }
    }
    throw ultimoError;
}

Cada AiClient (CerebrasAiClient, GeminiAiClient, MistralAiClient, SambaNovaAiClient, CloudflareAiClient) implementa completar(), getModeloId() (formato "<proveedor>:<modelo>", ej. cerebras:gpt-oss-120b) y disponible() — si no hay API key configurada para uno, se salta solo de la rotación sin tocar código. Cloudflare tiene un shape de respuesta distinto (no compatible OpenAI): usa account_id en la URL y devuelve {"result":{"response":"..."},"success":bool} en vez de choices[].message.content.

Modo solo cloud (ai.local.habilitado=false) — producción por defecto

private AiRespuesta usarSoloGroq(...) { // nombre heredado, ya no es solo Groq

Modo orquestado (ai.local.habilitado=true)

// El proveedor cloud de turno responde al usuario; Ollama compara en background
private AiRespuesta usarLocalConFallback(...) {
    RespuestaCloud r = completarConRotacion(prompt, contenido, maxTokens);
    Long id = guardarDataset(tipo, contenido, prompt, null, r.contenido(), ollama.getModeloId(), r.modeloUsado(), ...);
    lanzarOllamaAsync(id, tipo, prompt, contenido, maxTokens); // no bloquea
    return new AiRespuesta(r.contenido(), r.modeloUsado(), false, id);
}

private void lanzarOllamaAsync(Long datasetId, String tipoEntrada, ...) {
    CompletableFuture.runAsync(() -> {
        String respuestaLocal = ollama.completar(prompt, contenido, maxTokens);
        double scoreLocal = "URL".equals(tipoEntrada) ? imiCalculator.calcularUrl(respuestaLocal) : imiCalculator.calcular(respuestaLocal);
        // Guarda scoreLocal + divergencia (|scoreLocal - scoreProveedorCloud|) en EntrenamientoDataset
        datasetRepo.findById(datasetId).ifPresent(d -> { d.setRespuestaLocal(respuestaLocal); d.setScoreLocal(scoreLocal); recalcularDivergencia(d); datasetRepo.save(d); });
    });
}

VeriAiRetryScheduler

Scheduler Spring (@Scheduled) que reprocesa automáticamente las entradas del dataset sin respuesta local. Diseñado para ser resiliente ante reinicios del servidor: en cada arranque, el cron hourly detecta entradas pendientes y las procesa.

Ciclo de ejecución


  Cada hora (cron: 0 0 * * * *)
    → ¿AI_LOCAL_HABILITADO=false? → return (prod: no hace nada)
    → Crear JobEjecucion { tipo="AUTOMATICO", estado="EJECUTANDO" }
    → Buscar EntrenamientoDataset WHERE respuesta_local IS NULL
      AND texto_input IS NOT NULL AND prompt_sistema IS NOT NULL

        → ollama.completar(entry.promptSistema, entry.textoInput, maxTokens)
        → Guardar respuesta_local + score_local + divergencia
        → Actualizar procesados/errores en JobEjecucion (live progress)

Plantillas de email

Reutiliza el método genérico EmailService.enviarNotificacion(destinatario, asunto, html) — ya existía en EmailService pero sin ningún caller previo. Dos plantillas HTML nuevas, enviarAvisoRachaEnRiesgo() y enviarAvisoCambioFuente(), construidas con un builder HTML compartido buildAvisoHtml que reutiliza el mismo estilo visual que el email de verificación de cuenta ya existente (EmailService.buildVerificacionHtml).

Sin opt-out de usuario por ahora — decisión explícita, se puede añadir un flag más adelante si hace falta.

Bloqueado en producción: igual que el resto de emails transaccionales (ver Variables de entorno y EmailService), el envío por Gmail SMTP no funciona de forma fiable en Render — la causa exacta no está confirmada al 100% (posible problema de TLS/SSL en la conexión SMTP saliente, o bloqueo de puerto por parte del cloud provider). En local funciona sin problema. Mientras tanto, estos avisos son efectivos solo en desarrollo.

Seguridad JWT

Implementada en JwtUtil.java y JwtFilter.java. Sin sesiones de servidor — cada request es validado independientemente.

Generación del token

// JwtUtil.java — HMAC-SHA256 con clave de al menos 32 chars
public String generateToken(String username) {
    return Jwts.builder()
        .subject(username)           // email del usuario
        .issuedAt(new Date())
        .expiration(new Date(System.currentTimeMillis() + expirationMs))
        .signWith(secretKey)         // HMAC-SHA256
        .compact();                  // header.payload.signature
}

Validación en cada request (JwtFilter)

// JwtFilter.java — ejecutado antes de cada controller
String header = request.getHeader("Authorization");

EmailService

Servicio Spring que envía emails HTML via Gmail SMTP usando JavaMailSender. La configuración SMTP se inyecta desde variables de entorno.

Configuración SMTP

# application.properties
spring.mail.host=smtp.gmail.com
spring.mail.port=587
spring.mail.username=${MAIL_USERNAME:}
spring.mail.password=${MAIL_PASSWORD:}  # App Password de Gmail, no la contraseña normal
spring.mail.properties.mail.smtp.starttls.enable=true

Método de envío

private void enviar(String to, String subject, String html) {
    if (from == null || from.isBlank()) {
        log.warn("[EMAIL] MAIL_USERNAME no configurada — email omitido");
        return;
    }
    MimeMessage message = mailSender.createMimeMessage();
    MimeMessageHelper helper = new MimeMessageHelper(message, true, "UTF-8");
    helper.setFrom(from);
    helper.setTo(to);
    helper.setSubject(subject);
    helper.setText(html, true);  // true = HTML
    mailSender.send(message);
}
